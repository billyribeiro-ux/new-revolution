# Blog audit and 0DTE implementation plan

**Date:** November 5, 2026. **Baseline:** `e896ebc`. **Verdict:** the CMS has a working, tested publishing foundation, but the proposed article does **not** line up for publication as written. Correct the content and integration blockers below, prepare a CMS draft, and verify it before considering launch.

This change delivers an audit, reproducible probes, evidence and an [agent publishing guide](../../../blog%20implementation.md). It does not publish the article, replace the 40 placeholders, change application behavior, remove launch protection, migrate a hosted database or deploy. The original untracked article brief remains unchanged; [input.json](input.json) records its SHA-256 and [draft-reviewed.txt.gz](draft-reviewed.txt.gz) preserves the exact reviewed bytes.

## Scope and evidence boundaries

Reviewed the four public blog loaders/templates, error handling and legacy redirects; admin post list/new/edit and remote/REST entry points; input schemas, service writes, transactions, revisions, autosave and preview tokens; taxonomy/authorship; TipTap HTML and sanitization; media upload/storage/variants; scheduled publishing; metadata/JSON-LD; RSS, sitemap, caching and the launch gate. Parsed all **40 archived article packages and 201 image specifications**. Inspected the target 0DTE brief's research, metadata, schema, image plan and complete article copy.

Measured the existing production build locally using the automatically seeded **two public posts and one protected post**. [http.json](http.json) has 19 route readings; [browser-results.json](browser-results.json) has 16 Chromium page/viewport readings and the resolved internal link checks. The browser checks used widths 320, 375, 768 and 1440. Screenshots were visually inspected: [index mobile](index-375.png), [index desktop](index-1440.png), [article mobile](article-375.png), [article desktop](article-1440.png).

This is a blog engineering/content audit, not a declaration that the whole site's SEO standard has been re-certified. The global `seo-audit.md` implement-and-recertify workflow was read but is not claimed complete by this planning deliverable. The 40 archived financial articles were parsed for compatibility, not individually fact-checked. Hosted CMS contents, CDN propagation, real broker permissions, author credentials, Search Console and field Core Web Vitals were not verified. Those limitations do not replace the local checks above.

## Proposed implementation sequence

### Phase A — Correct the editorial package

1. Preserve the source brief and create a separate reviewed publication package. Keep research/competitor notes out of the public body.
2. Resolve every content-table blocker. Obtain owner confirmation for the real desk workflow, author title and offer promises; obtain a current broker source for any named-account strategy permissions. Remove unverifiable statistics rather than fabricating replacements.
3. Keep the proposed slug `0dte-spx-options-strategy-guide` only after checking CMS uniqueness and deciding how it relates to archived post #02 and the risk-management article. No old slug is deleted/redirected merely because the new guide exists.
4. Candidate metadata, already counted: title **`0DTE SPX Options Strategy Guide`** (31 raw / 57 with brand); description **`Explore a 0DTE SPX options strategy with defined-risk spread examples, settlement mechanics, gamma assumptions, execution costs, and position limits.`** (149). Confirm these still describe the final reviewed article.
5. Prepare supported HTML and 3–5 useful plain FAQ pairs. Use readable arithmetic, semantic tables, sourced/hypothetical labels and a visible disclosure. Correct all CTA destinations and remove claims of proven positive expectancy without an empirical record.

**Exit evidence:** reviewed claim ledger, source dates, calculation checks, exact metadata counts and a link map with successful responses. No claim of search ranking is an acceptance criterion.

### Phase B — Produce and upload the assets

Create the five planned graphics only after the numbers/text are corrected. Use actual chart data with provenance or conspicuous hypothetical labels. The tax graphic must include its top-marginal/base-rate assumptions; payoff diagrams must distinguish terminal payoff from expected return. Upload through the existing media pipeline, preserve the returned URLs/variants/crops, and set accurate alt text/captions.

**Exit evidence:** all image/variant bytes decode correctly, real dimensions recorded, mobile readability checked, no placeholder SVGs/zero-byte specifications used as finished media.

### Phase C — Address CMS launch blockers in separate scoped changes

Prioritize B03/B04/B05, dependency triage, and the author/metadata/time-policy inconsistencies. Fix the 320px related-card overflow. Add meaningful regression cases that fail on the current defect and pass after repair; do not enshrine the broken behavior shown by these audit probes as a passing policy. A reusable single-post importer is optional; ordinary CMS/service draft entry already exists.

Keep the Vite+ catalog alignment and all existing thresholds. If a cache purger is selected, implement and measure it on a protected deployed Preview. Do not equate a successful in-memory invalidation test with a real CDN purge.

**Exit evidence:** source changes with tests, Svelte MCP results for affected components, actual preview before/after output and green repository gates. Any unresolved launch risk remains explicit.

### Phase D — Enter and review one CMS draft

Follow [blog implementation.md](../../../blog%20implementation.md), resolve real taxonomy/author IDs, use uploaded media, and save as **draft**. Reload, compare persisted fields, inspect the signed preview, test all TOC/FAQ/table/image/CTA paths, and record the actual resulting gate score. No score is claimed here for the unconverted real article; the 100/100 probe is a synthetic demonstration of a gate weakness.

**Exit evidence:** actual draft ID/environment, saved payload, private preview checks, desktop/mobile review and no public draft leakage. Keep preview tokens out of tracked artifacts.

### Phase E — Publish and launch as distinct steps

After editorial acceptance, publish the one reviewed record using the normal service/editor and its actual publication instant. While `/blog` remains gated, verify noindex/no canonical and sitemap exclusion. Launch the section only after the owner authorizes it and the launch tracker is satisfied for **all** content exposed by removing the prefix. Remove/replace placeholder posts through an explicit inventory decision, not a mass importer flag.

Verify hosted storage, scheduled sweep/cron, real cache withdrawal, canonical origin, RSS/sitemap and article identity in the deployed environment. Submit/inspect through Search Console only with appropriate access; local or search-tool results cannot certify indexing.
