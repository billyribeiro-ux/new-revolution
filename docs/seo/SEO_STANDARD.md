# Technical SEO Standard — Svelte 5 / SvelteKit

> **Blog work — November 5, 2026:** Read the mandatory blog handoff at repository-root `docs/BLOG_AGENT_HANDOFF.md` before adding or changing articles, editor workflows, blog SEO or automation. It distinguishes the existing CMS workflow from the proposed intake tooling.

> **Fonts and article fragments — November 5, 2026:** Follow repository-root `docs/FONT_AND_FRAGMENT_POLICY.md`. Same-origin font hrefs and native TOC anchors are valid; verify request origins and keep section fragments out of page canonicals.

**Verified:** 2026-11-01 (every `G:` row below was re-fetched from developers.google.com on 2026-11-01; the page's own "Last updated" date is quoted where a rule depends on it. Rows that still carry **†** were not re-verified.)
**Scope:** Technical SEO only. This standard makes every page crawlable, indexable, fast, and eligible for rich results. Rankings beyond that depend on content and links. SvelteKit's own SEO page says: _"The most important aspect of SEO is to create high-quality content that is widely linked to from around the web."_

## How to read this document

- Every requirement has an **ID** (e.g. `IDX-05`). The audit prompt (`seo-audit.md`) reports PASS / FAIL / N-A / BLOCKED per ID, per URL or template, with evidence.
- **Source** shows where the requirement comes from:
  - `SK:<page>` — svelte.dev/docs/kit/<page>, last re-fetched 2026-10-31.
  - `G:<topic>` — Google Search Central documentation.
  - `[house rule]` — an engineering choice, not a Google or Svelte requirement. It is labelled so nobody mistakes it for one.
- Items marked **†** were not re-verified on 2026-11-01. The audit agent **must fetch the cited page** before relying on them.
- **Version caveat:** SvelteKit 3 went stable in October 2026, and the Svelte MCP docs now describe it (e.g. `$app/env`, `#lib/...`). A repo may still be on 2.x, where those are `$app/environment` and `$lib`. Always use the APIs of the version **installed in the repo** (see `package.json` and the lockfile). Migrating to 3 (`pnpm dlx sv migrate sveltekit-3`) is a separate, owner-approved task, not part of this audit. SvelteKit 3 changes that matter here: Node 22 and Vite 8 minimums; adapter-node replaces the `ORIGIN` env var with `kit.paths.origin`; `base` and `assets` are removed from `$app/paths`; shallow routing moves from `pushState`/`replaceState` to `goto(..., { state })`; `@sveltejs/enhanced-img` 1.x requires Vite 8.

## 10. YMYL and trust (YMYL) — mandatory for trading, finance and investing content

Google says that for topics affecting health, finances, safety or societal well-being, its systems "give even more weight to content that aligns with strong E-E-A-T", and that trust is the most important part of E-E-A-T. E-E-A-T is not a ranking factor itself. These requirements make trust **visible and verifiable**. The agent can check that the elements exist; the owner must confirm they're true.
