## Article refresh investigation and fixes

The reported localhost article was inspected through CSS source tracing, live browser cascade inspection, saved frame captures, and image-paint comparison. The final findings and corrections are recorded here, with the original pasted diagnosis preserved outside the checkout.

- The original global `li` rule directly applied the 16px body size to TOC items, overriding the 14px size inherited from `.toc-list`. Shared `p` and `li` defaults now inherit size and leading from their component, with scoped `.toc-item { font-size: inherit; }` retaining the intended role. Live list, item, and link sizes now compute to 14px.
- The expanded TOC originally changed height as text wrapping settled. CSS now reserves its available viewport height, and the attachment uses that rendered boundary. Recorded Chromium, Firefox, and WebKit captures remain at 888px at 1920×1000. Native collapse and internal scrolling remain available. Short-viewport probes were vertically bounded. Root-font doubling exposed an existing horizontal rail displacement, so complete 200% text accessibility remains unverified.
- A scrolled refresh originally painted at 0 before Kit restored 450 roughly 100ms later. The root layout now saves a short-lived, single-use page-position snapshot and restores matching reloads from its parser-time head script before client modules arrive. Current held-module captures start at 450 in all three engines. Direct mentorship controls verify reload, SPA navigation, back, and fragment handling across three engines.
- The cover box stayed 1424×801 while asynchronous decoding allowed a blank bitmap frame. The cover now uses synchronous decoding. Direct Chromium paint captures show the bitmap in the first new frame at both the top and saved reading position, removing the recorded 16.7ms blank frame.

The live cover cascade comes from its scoped article rule plus shared reset declarations. The prose selectors do not match the cover. The source and runtime inspections found complete SSR styles. The captured critical style measures 270,580 characters and 270,623 UTF-8 bytes. The native root stylesheet provides persistent font declarations. A remaining development critical-style removal rebuilt the FontFace objects. Strong-reference and pixel controls isolated that event, and the documented T17 development-only HTML transform retains the generated component stylesheet. The top-of-page TOC active row also renders in SSR.

## Performance acceptance

Three anonymous requests to the existing deployed staging article returned CDN `HIT`, age 246–247 seconds, with TTFB **121.25ms, 121.40ms, and 122.28ms**. This proves the existing edge cache was working during the sample; it does not measure a new local code improvement. The owner’s hosted sub-100ms target is **not proven or met by these samples**. Dynamic SSR remains necessary for the existing immediate CMS-publication contract; changing the article to build-time prerendering would change that behavior.

A later five-transfer HTTP/2 probe reused one anonymous connection. Before publication, its initial CDN MISS measured 370.149ms. The following four CDN HITs measured **57.169ms, 51.656ms, 33.147ms, and 36.000ms**, with zero new connections and identical response bodies. This establishes sub-100ms warm-cache delivery in that transport condition. Cold misses remain above the target, and these baseline observations establish no improvement from unpublished changes. The reproducible command and raw headers remain under `performance-keepalive-before-push/` in the evidence directory.
