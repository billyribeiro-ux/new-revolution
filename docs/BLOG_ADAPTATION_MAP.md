# Blog System Adaptation Map (`tx-360` to `new-revolution-web`)

> **Blog work — November 5, 2026:** Read the [mandatory blog handoff](BLOG_AGENT_HANDOFF.md) before adding or changing articles, editor workflows, blog SEO or automation. It distinguishes the existing CMS workflow from the proposed intake tooling.

> **Fonts and article fragments — November 5, 2026:** Follow the [verified policy](FONT_AND_FRAGMENT_POLICY.md). Same-origin font hrefs and native TOC anchors are valid; verify request origins and keep section fragments out of page canonicals.

For current Vite+ commands, test projects and upgrade guidance, see [`VITE_PLUS_WORKFLOW.md`](VITE_PLUS_WORKFLOW.md). This map records the blog adaptation rather than a new toolchain setup.

| `tx-360` Concept             | `new-revolution-web` Equivalent / Adaptation                                                                                                                                                                                                                                                                                                                                                              |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Framework                    | SvelteKit `^3.1.1` + Svelte `^5.57.3` with compiler runes enforced (`vite.config.ts`) and experimental `remoteFunctions: true` + `async: true`.                                                                                                                                                                                                                                                           |
| Database & Driver            | Drizzle ORM (`drizzle-orm@^0.45.4`) with `postgres` (`postgres-js`, `drizzle-orm/postgres-js`) for production/TCP Postgres (interactive `db.transaction` supported) and `@electric-sql/pglite` (`drizzle-orm/pglite`) fallback when `DATABASE_URL` is the placeholder `postgres://user:password@host:port/db-name` or in hermetic test suites.                                                            |
| Authentication & Admin Guard | `better-auth@^1.7.15` (`src/lib/server/auth.ts`, `src/lib/server/db/auth.schema.ts`, `src/hooks.server.ts`). `user.id` is `text` PK; added `role` (`'user' \| 'admin'`) to `user` table and `requireAdmin(event)` guard in `src/lib/server/auth-guard.ts`. `revisions.user_id` and `audit_log.actor_user_id` reference `user.id` (`text`, `ON DELETE SET NULL`).                                          |
| Validation                   | `zod@^4.6.7` in `src/lib/shared/schemas/` (Standard Schema compatible with SvelteKit 3 remote functions and server routes).                                                                                                                                                                                                                                                                               |

| HTML Sanitizer               | `sanitize-html@^2.18.1` centralized in `src/lib/sanitize-post-html.ts`.                                                                                                                                                                                                                                                                                                                                   |
| Image Pipeline & Storage     | `sharp@^0.35.5` + `@vercel/blob@^2.8.2` (Vercel Blob when `BLOB_READ_WRITE_TOKEN` is set; otherwise, in development only, a persistent local disk driver under `.data/media` served by `/media/[...path]`; production without a token refuses uploads. The existing static marketing hub at `/blogs` (`src/routes/blogs/+page.svelte`) is preserved so existing unit and E2E tests (`src/routes/blogs/page.svelte.spec.ts`, `src/routes/page.svelte.e2e.ts`) continue to pass without modification. |
