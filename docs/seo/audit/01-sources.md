## 2. Official Svelte MCP Documentation Fetched (`SK:*`)

All `SK:*` sections cited in `SEO_STANDARD.md` were fetched via the `svelte` MCP `get-documentation` tool in this session:

- `SK:seo` (`[DOC https://svelte.dev/docs/kit/seo §SEO]`): SSR enabled by default; normalized URLs via `trailingSlash`; `<title>` and `<meta name="description">` in `<svelte:head>` driven by `page.data` (`$app/state`) in root `+layout.svelte`; dynamic `/sitemap.xml` via `+server.ts`.
- `SK:page-options` (`[DOC https://svelte.dev/docs/kit/page-options §Page options]`): `prerender` (`true` | `false` | `'auto'`), `entries()`, `ssr` (default `true`), `csr` (default `true`), `trailingSlash` (`'never'` default, `'always'`, never `'ignore'`).
- `SK:performance` (`[DOC https://svelte.dev/docs/kit/performance §Performance]`): `@sveltejs/enhanced-img`, font preloading via `resolve(event, { preload })` in `src/hooks.server.ts`, streaming non-essential data from server `load`, avoiding waterfalls, minimizing third-party scripts.
- `SK:configuration` / `SK:@sveltejs-kit-vite` (`[DOC https://svelte.dev/docs/kit/@sveltejs-kit-vite §sveltekit]`): In SvelteKit 3, configuration is passed directly to `sveltekit({ ... })` in `vite.config.ts`, including `adapter`, `prerender` (`handleHttpError`, `handleMissingId`, `handleUnseenRoutes` all defaulting to `'fail'`), `csp`, and `version`.
- `SK:errors` (`[DOC https://svelte.dev/docs/kit/errors §Errors]`): `error(status, message)` from `@sveltejs/kit` throws an HTTP error rendered by `+error.svelte` with the exact status code (`404`, `410`, etc.).
- `SK:accessibility` (`[DOC https://svelte.dev/docs/kit/accessibility §Accessibility]`): Unique `<title>` per route drives client-side route announcements; focus management resets to `<body>`; `<html lang="...">` in `src/app.html`.
- `SK:cli/paraglide` (`[DOC https://svelte.dev/docs/cli/paraglide §paraglide]`): Paraglide JS 2 via `npx sv add paraglide` (only when multiple locales are configured).
- `SK:images` (`[DOC https://svelte.dev/docs/kit/images §Images]`): `enhancedImages()` plugin before `sveltekit()` in `vite.config.ts`; `<enhanced:img>` with `sizes` for wide images; `fetchpriority="high"` and no `loading="lazy"` on LCP image.
- `SK:hooks` (`[DOC https://svelte.dev/docs/kit/hooks §Hooks]`): `handle({ event, resolve })` in `src/hooks.server.ts` intercepts requests, sets headers, and configures `preload` and `transformPageChunk`.
- `SK:load` (`[DOC https://svelte.dev/docs/kit/load §Loading data]`): `PageLoad` / `PageServerLoad` / `LayoutLoad` / `LayoutServerLoad`; `page.data` in `$app/state` typed via `App.PageData` in `src/app.d.ts`.
- `SK:routing` (`[DOC https://svelte.dev/docs/kit/routing §Routing]`): Route files `+page.svelte`, `+page.ts`, `+page.server.ts`, `+layout.svelte`, `+layout.ts`, `+layout.server.ts`, `+server.ts`, `+error.svelte`.
- `SK:migrating-to-sveltekit-3` (`[DOC https://svelte.dev/docs/kit/migrating-to-sveltekit-3 §Migrating to SvelteKit v3]`): `$app/env` replaces `$app/environment`; `#lib` replaces `$lib`; `vite.config.ts` `sveltekit({...})` replaces `svelte.config.js`; `redirect(..., { external: true })` for external redirects.
